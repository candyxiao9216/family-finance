# /knowledge-distillation

## 适用场景
- 独立做知识沉淀，不走完整 devflow 流程
- 用户说"帮我做知识沉淀"、"总结这次需求的经验"、"记录踩坑"、"做个复盘"

## 执行步骤

### 第一步：信息收集
收集以下来源的信息：

| 来源 | 关注要点 |
|------|---------|
| 需求分析产物 | 关键决策、澄清的歧义、识别的边界 |
| 技术方案产物 | 架构决策理由、方案取舍 |
| 代码实现 | 踩过的坑、关键改造模式 |
| 测试产物 | 缺陷模式、易出错场景 |
| 审查记录 | 被打回原因、关键修订 |

### 第二步：提炼（4 项标准）
每条知识点必须满足：可复用 · 具体明确 · 结论导向 · 精简（1-3句）

### 第三步：分类输出

```markdown
## {标识} - {标题} ({日期})

### 业务知识
- ...

### 技术决策
- ...

### 改造模式
- ...

### 踩坑记录
- ...

### 流程改进
- ...
```

### 第四步：写入文件
- 用户指定路径 → 写入该路径
- 未指定 → 询问保存位置，建议：`docs/knowledge/{标识}.md`
- **规则：只追加，不覆盖；同一需求多次执行时检查是否已存在章节**

## 质量自检
- [ ] 每条知识是否满足 4 项标准？
- [ ] 是否有大段复制粘贴？（应提炼为精简结论）
- [ ] 不了解本次需求的人能看懂吗？
