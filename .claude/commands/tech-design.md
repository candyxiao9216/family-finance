# /tech-design

## 适用场景
- 独立生成技术方案，不走完整 devflow 流程
- 用户说"帮我写技术方案"、"出一个设计文档"、"给这个需求出方案"

## 执行步骤

### 第一步：解析需求输入
- 若传入文件路径 → 读取文件提取需求信息
- 若传入口头描述 → 若信息不足，追问：核心功能、涉及模块、性能/安全要求、数据量级

### 第二步：生成技术方案
按以下结构生成（删除不涉及的章节，不强行填写）：

```markdown
# 技术方案：{需求名称}

## 背景与目标
## 方案概述
## 架构设计（Mermaid 图）
## 核心实现路径
## 数据库 / 接口变更（如有）
## 关键技术决策
> 选 A 方案，原因：... 不选 B 方案，原因：...
## 性能与安全考量
## 不在范围内的事项
```

### 第三步：保存文档
- 用户指定路径 → 保存到该路径
- 未指定 → 询问保存位置，建议：`docs/tech-design-{需求名}.md`

## 注意事项
- 架构图、流程图统一用 Mermaid 语法
- 关键决策必须说明"选这个的原因"和"不选那个的原因"
- 信息不足时标注"待补充"并说明缺少什么
